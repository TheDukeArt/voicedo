# VoiceDo — план разработки

Десктоп-приложение для перевода речи в текст с помощью ИИ: заменяет ввод с клавиатуры, срабатывает по глобальному сочетанию клавиш.

## Требования (зафиксированы)

- Платформы: **Windows + macOS**
- Тип: **трей-приложение / фоновый агент** + видимое окно настроек
- Язык: **Rust**, приоритет — малый размер и скорость
- Режим работы: **push-to-talk** (держать клавишу и говорить; отпустил — распознавание и вставка текста)
- ASR-бэкенд: **OpenAI-совместимый эндпоинт** (`/v1/audio/transcriptions`), адрес и токен задаёт пользователь
- Настройки: эндпоинт, токен, модель, язык + **кнопка проверки подключения**

## Выбор стека

| Компонент | Выбор | Обоснование |
|---|---|---|
| Каркас | **Tauri 2** | Rust-бэкенд, бинарник ~5–10 МБ (против ~150 МБ у Electron), WebView из ОС; встроенные плагины: трей, global-shortcut, autostart, store, updater |
| Фронтенд | **Svelte + TypeScript** | Минимальный бандл (<500 КБ), простой код для формы настроек; официальный шаблон `create-tauri-app` |
| Захват аудио | **`cpal`** | Кроссплатформенный захват микрофона, чистый Rust |
| HTTP | **`reqwest`** | Multipart-запрос на ASR-эндпоинт |
| Вставка текста | **`enigo`** | Кроссплатформенная эмуляция клавиатуры, поддержка юникода/кириллицы |
| Хранение настроек | **`tauri-plugin-store`** | JSON в appdata, без внешнего БД |

Отклонённые альтернативы: чистый `tray-icon + muda + winit` (всё вручную, дороже), Slint (лицензия), Electron (размер), WPF/SwiftUI (только одна ОС).

### Поток работы

```
Нажал хоткей   → событие Pressed   → старт записи микрофона (индикатор «запись» в трее)
Отпустил       → событие Released  → остановка записи
                                    → WAV → POST {endpoint}/audio/transcriptions
                                      (Bearer token; поля file, model, language)
                                    → полученный текст → enigo печатает в активное приложение
                                    → индикатор «готов»
Ошибка на любом шаге → иконка «ошибка» + всплывающее уведомление трея
```

### Параметры аудио

- Частота: **16 кГц, моно, 16-bit PCM** (стандарт для ASR)
- Формат отправки: **WAV** (`audio/wav`)
- Таймаут запроса: **60 с**

### Формат запроса к ASR (OpenAI-совместимый)

```
POST {endpoint}/audio/transcriptions
Authorization: Bearer {token}
Content-Type: multipart/form-data

file     = audio.wav
model    = {из настроек, по умолчанию "whisper-1"}
language = {из настроек или авто}
```

Ответ: `{ "text": "..." }` → вставка `text` через `enigo`.

### Формат запроса к ASR (Qwen/DashScope, native)

```
POST {endpoint}   # используется как есть, без склейки путей
Authorization: Bearer {token}
Content-Type: application/json
X-DashScope-SSE: disable

{"model":"qwen-audio-3.0-asr-flash",
 "input":{"messages":[{"role":"user","content":[
   {"type":"input_audio","input_audio":{"data":"data:audio/wav;base64,..."}}]}]},
 "parameters":{"format":"wav","sample_rate":"16000"}}
```

Ответ: `output.output.text` (фолбэки `output.text`, `output.output.sentence.text`).
Язык пока не передаётся (TODO). Ошибка `ASR_RESPONSE_HAVE_NO_WORDS` трактуется как
«сервер доступен, речи нет» (успех для теста тишиной).

### UI окна настроек (Svelte)

Поля:
- **Провайдер** — «OpenAI-совместимый» / «Qwen (DashScope)»; при смене подставляются дефолтные эндпоинт/модель
- **Эндпоинт** — базовый URL API (валидация формата)
- **Токен** — поле с маскировкой (показ/скрытие)
- **Модель** — текст, по умолчанию `whisper-1`
- **Язык** — «авто» или конкретный
- **Хоткей** — запись сочетания клавиш из клавиатуры

Кнопка **«Проверить подключение»**:
1. Генерирует короткий тестовый WAV (тишина ~0.1 с)
2. Отправляет его на эндпоинт с текущими настройками
3. Показывает результат: успех (задержка мс + распознанный текст) или ошибку (статус/сообщение)

Сохранение: автоматически через `tauri-plugin-store`.

### Трей

Иконка с состоянием: **готов / запись / обработка / ошибка** (меняется визуально).
Меню: «Показать настройки», «Выход». Закрытие окна сворачивает приложение в трей, не завершает.

## План работ (по шагам)

1. **Каркас** — `cargo create-tauri-app` (шаблон Svelte/TS), настройка `tauri.conf.json`: окно настроек, скрытие в трей вместо выхода
2. **Настройки (UI)** — форма на Svelte, валидация, кнопка теста подключения, сохранение в store
3. **Хоткей** — `tauri-plugin-global-shortcut` v2, события `Pressed`/`Released`, смена хоткея из UI; по умолчанию `Ctrl+Shift+Space` (Win) / `Cmd+Shift+Space` (macOS)
4. **Запись** — `cpal`: захват 16 кГц моно в кольцевой буфер, кодирование в WAV по остановке
5. **Распознавание** — `asr.rs`: multipart-запрос, обработка ошибок сети/авторизации/статусов
6. **Вставка текста** — `typer.rs`: задержка ~50 мс после отпускания клавиши (настраиваемая), `enigo::text_input` в активное приложение
7. **Трей** — иконки состояний, меню, уведомления об ошибках
8. **Разрешения (macOS)** — запрос доступа к микрофону и Accessibility при первом запуске; понятная ошибка при отказе
9. **Полировка** — обработка ошибок, логирование (`tauri-plugin-log`), автостарт (опционально)
10. **Сборка** — локально `cargo tauri dev` / `cargo tauri build`; CI (`.msi`/`.dmg`, подпись, автообновление) — отдельным этапом

## Риски и решения

| Риск | Решение |
|---|---|
| Разные хоткеи на Win/macOS | Настраиваемый хоткей, разные дефолты по ОС |
| `enigo` печатает раньше, чем целевое приложение вернёт фокус | Настраиваемая задержка перед вставкой (по умолчанию 50 мс) |
| Нет разрешения на микрофон (macOS) | Явная ошибка в трее + инструкция по выдаче разрешения |
| Нет разрешения Accessibility (macOS) | Текст не вставляется — отдельное уведомление с инструкцией |
| Эндпоинт не отвечает / 401 | Таймаут 60 с, отображение статуса и текста ошибки в трее и окне настроек |
| Кириллица/юникод при эмуляции ввода | `enigo` использует юникод-ввод на обеих платформах |
